# 不用服务器的更新检查

> 给桌面程序加「发现新版本」，但没有服务器、没有域名、没有备案、不想花钱。
>
> 这个仓库讲的是一套**思路**：把「版本清单」放在一个**地址固定、可匿名读取、国内可达**的静态位置上，程序只读不写。代码只是这套思路的一个通用实现。

---

## 一、问题长什么样

你发了一个 exe，用户装的是 v1.1.0。你出了 v1.2.0，怎么让他知道？

看起来有很多答案，国内个人开发者实际能用的却很少：

| 方案 | 现实阻碍 |
|---|---|
| GitHub Releases | 国内直连经常超时，程序启动就卡十几秒 |
| Gitee Releases | 要账号、要审核，外链还会变 |
| 自建 JSON / 对象存储 | 要服务器或要备案，还可能有费用 |
| 网盘分享（蓝奏云等） | 免费、国内快，但**没有 API** |

所以真正的约束不是「用什么协议」，而是：

1. **地址必须固定**——程序里写死的 URL 不能每发一版就变；
2. **必须能匿名读**——用户不该为了检查更新去登录；
3. **国内必须能连上**——否则等于没有；
4. **失败不能骗人**——读不到就说读不到，不能说「已是最新」。

## 二、核心思路：把网盘当只读的 KV

一条分享链接 = 一个 key，文件里的内容（文件名 / 列表）= value。

```
固定外链 ──► 目录
              ├─ app__v1.1.0.exe     ← 版本号写在名字里
              ├─ app__v1.2.0.exe
              └─ app__v1.3.0.exe
```

程序做的事只有三步：

1. 打开这个固定地址，读出**文件列表**；
2. 从文件名里用正则取版本号，**按数值取最大**；
3. 和当前版本比较，大了就提示，并给出该文件的下载页地址。

每发一版，你只是往目录里多放一个文件——**外链一个字母都不用改**。这是整套方案能成立的全部原因。

### 为什么是「目录」不是「单个文件」

单文件分享的文件 id 每传一版就会变，想让链接固定只能靠「改名」。而多数网盘的改名属于付费能力。目录分享则天然满足：链接锚在目录上，增删文件不影响它。

### 三种可替换的「源」

思路是通用的，网盘只是其中一种承载：

| 源 | 固定地址 | 版本从哪来 | 适合 |
|---|---|---|---|
| 网盘目录 | 分享链接 | 文件名 | 完全不想碰服务器 |
| 静态 JSON | 任意 HTTPS | JSON 字段 | 有对象存储 / Pages |
| Releases API | 仓库固定 | `tag_name` | 面向海外用户 |

`nou` 把三者统一成同一个接口：**给我一个版本号和下载地址，别的我不管**。

## 三、三条铁律

这三条比代码重要，少一条就会出事。

### 1. 失败必须显式失败

```
源挂了 → ok=false → 前端显示「检查失败 · 手动打开」
源挂了 → ok=true  → 前端显示「已是最新」   ← 灾难
```

第二行的危害在于**它是安全的错觉**：用户看到「已是最新」，就不会去手动看下载页，于是永远停在旧版。

推论：**回落源不能洗白主源的失败**。主源没读到版本、回落源又只能说「不比我新」，这时必须判定为「未知」，而不是「最新」。

### 2. 只探测，不执行

程序永远不要自动下载并替换自己的 exe。三个硬理由：

- **文件占用**：Windows 下运行中的 exe 不能覆盖，得先退出自己；
- **没有签名**：下载中断、或分享被替换成别的文件，程序无从分辨；
- **杀软**：一个 exe 静默改写另一个 exe，是最典型的木马行为。

正确姿势是：**提示 + 打开下载页**，替换交给用户。真要做「一键更新」，见第六节。

### 3. 版本真相只有一处

`APP_VER = "1.2.0"` 这个常量，和文件名里的 `v1.2.0`，必须同时更新。

只改一边的后果：

- 只改文件名 → 程序认为自己还是旧的 → **每次启动都提示更新**；
- 只改常量 → 上传的还是旧包 → 用户下完发现没变化。

建议把「打版本」做成一个脚本，一处输入、两处产出。

## 四、一次检查的时序

```
启动 ──► 页面加载
           │
           ├─ GET /api/update/check          （本地后端；只读、不带账号）
           │     ├─ 命中缓存？→ 直接返回（默认 30 分钟）
           │     └─ 未命中 → 读源 → 解析 → 比较 → 写缓存
           │
           └─ 前端拿到 {ok, current, latest, has_update, url}
                 ├─ ok=false        → 什么都不显示（手动检查时才提示）
                 ├─ has_update=false→ 什么都不显示
                 └─ has_update=true → 顶部标签 + 弹框（同一版本只弹一次）
                        └─ 「去下载」→ POST /api/open_url → 系统浏览器
```

几个容易被忽略的细节：

- **失败静默**：自动检查失败不要弹窗、不要 toast，用户没要求检查，别用红字吓他；
- **同一版本只弹一次**：看过就记下来（`localStorage` / 注册表），否则每次启动都拦一道，用户会卸载；
- **手动检查要与自动检查区分**：手动必须有反馈（含失败原因），自动必须安静；
- **缓存时间别太短**：检查更新不是实时业务，30 分钟起步，对源站礼貌，也避免自己启动变慢。

## 五、这套方案会踩的坑（实测）

> 下面每条都是真踩过的，不是设想。

1. **版本号按字符串比** → `v1.10.0 < v1.9.0`。必须拆成整数段比较。
2. **把「空目录」当错误** → 网盘的列表接口对空目录返回的是一个正常状态码，不是失败。要把「没有文件」和「读不到」分开。
3. **把「提取码错误」当网络错误** → 两种情况的重试策略完全相反：前者重试无用，后者值得重试。
4. **密码设了却没生效** → 网盘的「密码开关」默认关闭，只填输入框等于没设，页面仍然匿名可读。设完必须用**错误密码**复验一次，确认它真的拒绝了。
5. **页面里的令牌变量名是随机的** → 同一天里两个分享页，一个是 `iblq6x`，另一个是 `iay5fd`。写死变量名必炸；正确做法是按**字段名**取值，再把标识符解引用。
6. **不同域名行为不一致** → 同一个文件，`*.lanzoue.com` 的下载页标题正确，`*.lanzoup.com` 返回的是残页。下载页域名要单独固定，别用分享链接的域名拼。
7. **解析失败时页面结构变了，你却静默当成「最新」** → 见铁律 1。
8. **把账号密码或 cookie 写进客户端** → 客户端里的一切都是公开的。检查更新必须是**匿名只读**。

## 六、如果确实要「一键更新」

能。但这不是一个函数，是**两个进程**，而且顺序不能乱：

```
主程序：下载到临时文件 → 校验 sha256 → 写 update.json → 起 helper → 自己退出
helper：等旧 pid 消失 → 旧文件改名为 .old → 新文件就位 → 校验 → 启动 → 退出
新程序：启动时顺手清理过期的 .old
```

关键事实：**Windows 不允许覆盖正在运行的 exe，但允许改名。** 所以「先改名、再补位」
是唯一干净的路子（Chrome / Firefox 的更新器都是这个套路）。实测（Windows 11）：
一个跑着的进程，它的 exe 可以被 `os.replace` 改名，改完原位置是空的。

实现就在 `nou/apply.py`，helper 是**同一个 exe 带隐藏参数再起一次**，不用多发布一个二进制：

```python
import nou

# 1) 必须在任何业务逻辑之前
if nou.handle_helper_argv():
    return
nou.cleanup_old()                       # 删掉「上一次」留下的备份

# 2) 用户点「立即更新」时
staged = nou.stage_download(url, expected_sha256=sha)   # 下到同目录临时文件
nou.apply_update(staged)                # 起 helper，然后你必须自己退出
sys.exit(0)
```

`apply_update()` 返回之前只保证「helper 已经起来了」；真正的替换发生在你退出之后。
失败会写到 `<plan>.json.log`，回滚是自动的（先把旧文件改名保住，写失败就换回来）。

### 拿不到直链怎么办：让浏览器下载，程序「认领」

上面那行 `stage_download(url)` 假设你能拿到**文件直链**。蓝奏云这类网盘不行：
分享页里的 `/fn?<token>` 会把请求转到 `ajaxfile.php`，最后落到
`developer*.lanrar.com/file/<token>`，那里回的是 **阿里云 WAF 的人机验证**
（一个 4 KB 的挑战页 + `acw_sc__v2` 脚本），不带 JS 环境怎么都过不去；
带 cookie 再试则变成「系统发现您的网络异常」。换 `developer1/2/3`、换 `:661` 端口、
换 `lanzoue/lanzoup` 域名，全都一样。**这不是代码问题，是人家故意的。**

能过 WAF 的只有真浏览器。所以把更新拆成「两段」，各自只做自己擅长的事：

```
用户：点「去下载」 → 浏览器下载到 ~/Downloads（文件名里带版本和 sha 前缀）
程序：轮询 find_download() 认出那个文件 → 核 sha256 → apply_update() 换掉自己
```

文件名就是元数据：`<name>__v<X.Y.Z>__<sha256 前 16 位>.exe`。网盘的列表接口只给
「文件名 + 大小」，哈希不能指望它给——那就写进名字里，程序从名字里读回来。

```python
hit = nou.find_download(version=r.latest, sha_prefix=r.sha256[:16], name_hint="myapp")
if hit and hit.sha256_ok:
    nou.apply_update(hit.path, wait_pid=os.getpid())
    sys.exit(0)          # 剩下的交给 helper
```

给用户的体验是「点两下」：下载、然后回来点「已下载，帮我替换」。中间那一步没法省，
省了就等于要程序自己过 WAF。

### `.old` 的修改时间会被 rename 带走

Windows 的 rename 连**源文件的 mtime** 一起搬。旧 exe 往往是几天前构建的，于是新版
一启动 `cleanup_old(min_age=60)` 就判定「这是上次遗留的」，把刚做好的回滚副本删掉——
恰恰在新版本还没证明自己能跑的那几秒。所以改名之后必须 `os.utime(old, None)` 把
mtime 拉到「刚刚」（`apply.py` 里已处理）。

还有一个**顺序**上的事实：helper 是被「用户手上那个旧版本」拉起来的，所以对
`apply.py` 的任何修补，都要**再发一版**才对下一次升级生效。

### 为什么大多数项目不该开这个开关

| 风险 | 具体后果 |
|---|---|
| 没有代码签名 | 杀软拦下的不是「可疑」，而是「一个 exe 在改写另一个 exe」——这是木马的标准行为 |
| 装在 Program Files | 目标目录不可写，除非提权；UAC 弹窗比手动替换更吓人 |
| 下载中断 / 被替换 | 没验哈希就等于装了个来源不明的程序 |
| **老版本已经发布出去了** | helper 参数必须**在用户手上那个版本里就存在**，否则老版本没法自学更新——第一次升级只能手动 |
| 多实例 / 正在写数据 | 你以为只有一个进程要等 |

「提示 + 打开下载页」的复杂度是 1；「静默替换」的复杂度是 20，而且一旦出错就是
用户程序打不开。先用前者把版本号管起来，等签名、安装目录、单实例都理清了再动后者。

## 七、怎么用这份代码

### Python（后端 5 行）

```python
from nou import Checker
from nou.sources import LanzouFolder

ck = Checker(current="1.2.0", sources=[
    LanzouFolder("https://example.lanzou?.com/bXXXXXXXX", password="abcd"),
])
print(ck.check(force=True).to_dict())
# {"ok": true, "current": "1.2.0", "latest": "1.3.0",
#  "has_update": true, "url": "https://.../<file_id>", ...}
```

命令行也能直接试：

```bash
python -m nou check --lanzou-folder https://example.lanzou?.com/bXXXXXXXX \
                    --lanzou-pwd abcd --current 1.2.0 --json
```

### 前端（一段 JS）

```html
<script src="update-check.js"></script>
<script>
installUpdateCheck({ endpoint: '/api/update/check', storageKey: 'myapp_seen_ver' });
</script>
```

它负责：静默查一次、顶部标签、弹框、「同一版本只弹一次」、失败不打扰。

### 测试

```bash
python -m unittest discover -s tests -t . -v
```

单测只用**录制的固定样本**，CI 不联网——不要把别人的站点当测试机。

### 跑起来看一眼

```bash
python examples/serve.py --current 1.2.0 \
    --lanzou-folder https://example.lanzou?.com/bXXXXXXXX --lanzou-pwd ****
# 浏览器打开 http://127.0.0.1:8787/
```

这一页做了两件事：加载时静默查一次、点按钮强制查一次；`--current` 故意传旧版本，就能看到弹框和右上角的小标签。

## 八、安全与礼貌

- **匿名只读**：不登录、不带 cookie、不做任何写操作；
- **低频**：默认 30 分钟缓存，单次启动最多 1 次请求；
- **可识别**：User-Agent 里带上程序名和版本，对方排查时能认出你；
- **失败即降级**：源站异常时宁可不说，也不要高频重试；
- **不公开你的分享凭据**：这份代码里所有链接都是占位符。

另外，自动化访问网盘页面很可能**不符合对方的用户协议**。它属于「技术上可行、条款上灰色」，风险自负；正式产品请用自己的静态托管或对象存储。
